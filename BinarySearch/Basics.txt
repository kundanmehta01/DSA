# 🔎 Binary Search

Binary Search is an algorithm used to **search efficiently in a sorted search space**.

Instead of checking every element:

```text
1 2 3 4 5 6 7 8 9
        ↑
```

we repeatedly cut the search space in half.

### Complexity

| Approach | Time |
|---|---:|
| Linear Search | O(n) |
| Binary Search | **O(log n)** |

For example, with 1,000,000 elements:

- Linear search → potentially 1,000,000 checks
- Binary search → about **20 checks**

Because:

```text
1,000,000
→ 500,000
→ 250,000
→ 125,000
→ ...
→ 1
```

---

# 1. The Core Idea

Suppose:

```text
nums = [1, 3, 5, 7, 9, 11, 13]
target = 9
```

We maintain:

```text
left
right
```

Initially:

```text
left = 0
right = 6
```

Calculate middle:

```python
mid = (left + right) // 2
```

So:

```text
left       mid       right
 ↓          ↓          ↓
[1, 3, 5, 7, 9, 11, 13]
           7
```

Actually `mid = 3`, so `nums[mid] = 7`.

Target is `9`.

Since:

```text
9 > 7
```

and the array is sorted, we **know everything left of 7 is useless**.

So:

```python
left = mid + 1
```

Now:

```text
[9, 11, 13]
 ↑
left
```

Repeat.

---

# 2. The Basic Binary Search Template

This is the first template you should memorize:

```python
def binary_search(nums, target):
    left = 0
    right = len(nums) - 1

    while left <= right:
        mid = (left + right) // 2

        if nums[mid] == target:
            return mid

        elif nums[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return -1
```

### Understand these three cases

```python
if nums[mid] == target:
    return mid
```

Found it.

---

```python
elif nums[mid] < target:
    left = mid + 1
```

Middle is too small.

Because the array is sorted:

```text
everything before mid is also too small
```

So throw it away.

---

```python
else:
    right = mid - 1
```

Middle is too large.

Therefore:

```text
everything after mid is also too large
```

Throw it away.

---

# 3. Why `left <= right`?

This is important.

Suppose:

```text
left = 3
right = 3
```

There is still **one element** to check.

```text
[1, 3, 5, 7]
       ↑
    left/right
```

Therefore:

```python
while left <= right:
```

not:

```python
while left < right:
```

The `<=` allows us to check the final remaining element.

# 5. The MOST Important Thing: Binary Search Is a Pattern

Don't think:

> "Binary Search = searching an array."

That's too narrow.

Think:

> **Binary Search = repeatedly eliminating half of a search space using some monotonic property.**

This is why binary search appears in many problems where there isn't even a traditional "search for this number."

# 6. When Should I Think of Binary Search?

Use this checklist.

### ✅ Signal 1: Array is sorted


> Binary Search?

### ✅ Signal 2: "Find target"

For example:

Classic binary search.

Example:

# 7. Variation #1 — First Occurrence

Consider:

```text
nums = [1, 2, 2, 2, 3, 4]
target = 2
```

Normal binary search could return:

```text
index 1
index 2
index 3
```

But what if we specifically need:

> **first position of 2**

When we find `2`, don't stop.

Instead:

```python
answer = mid
right = mid - 1
```

Because maybe there is another `2` on the left.

Template:

```python
def first_occurrence(nums, target):
    left = 0
    right = len(nums) - 1
    answer = -1

    while left <= right:
        mid = (left + right) // 2

        if nums[mid] == target:
            answer = mid
            right = mid - 1

        elif nums[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return answer
```

### Key idea

Normal:

```text
found → STOP
```

First occurrence:

```text
found → save → search LEFT
```

---

# 8. Variation #2 — Last Occurrence

Same array:

```text
[1, 2, 2, 2, 3, 4]
```

Want the **last `2`**.

When found:

```python
answer = mid
left = mid + 1
```

Because maybe another `2` exists on the right.

Template:

```python
def last_occurrence(nums, target):
    left = 0
    right = len(nums) - 1
    answer = -1

    while left <= right:
        mid = (left + right) // 2

        if nums[mid] == target:
            answer = mid
            left = mid + 1

        elif nums[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return answer
```

### Memorize this:

```text
First occurrence → found → go LEFT

Last occurrence  → found → go RIGHT
```

---

# 9. Variation #3 — Lower Bound

This is a very important binary-search concept.

Suppose:

```text
nums = [1, 3, 5, 7, 9]
target = 6
```

There is no `6`.

We want:

> First element that is **>= 6**

That's `7`.

```text
[1, 3, 5, 7, 9]
          ↑
```

This is called a **lower bound**.

The condition we're searching for is:

```text
nums[mid] >= target
```

When true:

```python
answer = mid
right = mid - 1
```

Because maybe there is an even earlier valid answer.

---

# 10. Variation #4 — Upper Bound

Upper bound means:

> First element that is **> target**

Example:

```text
nums = [1, 3, 5, 5, 5, 7, 9]
target = 5
```

First element greater than `5`:

```text
7
```

Again, binary search.

# 11. Binary Search on the Answer ⭐

This is where Binary Search becomes really powerful.

Suppose the question says:

> Koko has piles of bananas. Find the minimum eating speed needed to finish within `h` hours.

Possible speeds:

```text
1
2
3
4
5
6
...
```

We're not searching an array for the answer.

We're searching:

```text
ANSWER SPACE
```

For each speed, ask:

> Can Koko finish within `h` hours?

The answers look like:

```text
Speed:    1  2  3  4  5  6  7  8
Can?      ❌  ❌  ❌  ❌  ❌  ✅  ✅  ✅
```

Notice the pattern:

```text
False False False False False True True True
                              ↑
                         first True
```

This is **monotonic**.

Once a speed works, every larger speed also works.

Therefore:

> **Binary Search!**

This is called **Binary Search on Answer**.

# 12. The Big Mental Model

There are basically two major forms you should learn:

### Form 1 — Search in a sorted array

```text
[1, 3, 5, 7, 9, 11]
 ↑              ↑
left           right
```

Search for a value/index.

---

### Form 2 — Search for the optimal answer

Example:

```text
Possible answers:

1  2  3  4  5  6  7  8
F  F  F  F  F  T  T  T
               ↑
          answer
```

Find:

```text
first True
```

or sometimes:

```text
last True
```

This pattern appears **a lot** in medium/hard LeetCode questions.

---

# 13. How to Identify Binary Search in Interviews

When reading a problem, ask these questions **in order**:

### Question 1

**Is the data sorted?**

If yes:

> Binary Search?

### Question 2

**Can I eliminate half the search space after each comparison?**

If yes:

> Binary Search.

### Question 3

**Am I looking for minimum/maximum possible value?**

If yes:

> Can I check whether a candidate answer is valid?

### Question 4

Does the validity look like:

```text
FFFFTTTT
```

or:

```text
TTTTFFFF
```

If yes:

> **Binary Search on Answer.**

# 14. Common Mistakes

### ❌ Mistake 1

Writing:

```python
mid = (left + right) / 2
```

In Python this produces a float.

Use:

```python
mid = (left + right) // 2
```

---

### ❌ Mistake 2

Using:

```python
left = mid
```

or:

```python
right = mid
```

This can cause an infinite loop.

Usually use:

```python
left = mid + 1
right = mid - 1
```

---

### ❌ Mistake 3

Forgetting the array must have some exploitable ordering.

Binary search isn't automatically applicable just because the input is an array.

---

### ❌ Mistake 4

Stopping at the first match when the question asks:

- first occurrence
- last occurrence
- minimum valid answer
- maximum valid answer

In these problems:

> **Finding a valid answer isn't necessarily the same as finding the desired answer.**
